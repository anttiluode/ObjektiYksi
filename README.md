# ObjektiYksi

**Object one. Trying to grasp for it.**

This repository asks a narrow computational-physics question that grew out of `ResonantNeuron`, `SighImageSuper`, `FunctionalArbors`, `Dig`, `TheMycelialCortex`, and `DendriteAsIteratedFeedbackOperator`:

> **Can persistent physical structure act as memory by generating useful operators when it is interrogated, while slow local changes rewrite the family of operators the structure can expose?**

The experiments are intentionally small, deterministic, and attackable. This is **not** a claim that cortex is an acoustic cavity, that arbitrary AI matrices can be stored in this lattice, that the biological credit-assignment problem is solved, or that this simulator has a hardware advantage.

## The object

The persistent state is one material vector `g`, not a bank of explicit learned matrices.

At fixed material, the resonant lattice is linear:

```math
H_g(\omega)=\left[K(g)-\omega^2I+i\omega\Gamma\right]^{-1}.
```

Choosing input and output ports exposes an effective transfer operator

```math
M_g(a)=P_{\mathrm{out}}H_g(\omega)P_{\mathrm{in}}(a),
```

where an address `a` may include source position, carrier frequency, or port choice.

For a vector input `x`, inference is simply

```math
y=M_g(a)x.
```

So the current picture is:

```text
persistent memory       g
question / address      a
exposed weight-like map M_g(a)
input                    x
computation              y = M_g(a)x
slow local learning      g -> g'
next query               exposes M_g'(a)
```

The matrix-like object is **generated by the material when queried**. It is not separately stored as a digital array.

That distinction became experimentally meaningful only at Gates 10–11.

## What the gates established

GitHub Actions reproduces the stack on Python 3.11 and 3.12.

### Gates 0–1 — topology is an operator, not merely a road

Gate 0 starts from mirror-symmetric material and uses an exact forward/reference sensitivity as a positive-control write rule. A fixed material budget is redistributed so later source-only replay strongly favors the chosen receiver.

Gate 1 shows why shortest-path language is insufficient: the learned target can be the strongest resonant output even when an ordinary `1/g` graph path is cheaper to the decoy.

The functional object is therefore

> **material arrangement + phase + resonance + frequency**, not merely connectivity.

### Gates 2–3 — local dither plus one scalar consequence can carve it

Gate 2 removes the analytic gradient and reciprocal receiver reference from learning. A proposal changes only two adjacent couplings:

```text
g_a <- g_a + delta
g_b <- g_b - delta
```

so total material is conserved. A delayed scalar consequence decides whether the physical perturbation survives.

Gate 3 makes the strongest competing output change during learning without telling the structural rule which competitor caused the error. The target still becomes rank-1 in every run.

### Gates 4–5 — one material supports a family of relations

Gate 4 freezes the learned material and varies source position and frequency. The same `g` exposes different transfer behavior depending on how it is queried.

Gate 5 trains one conserved material against several source landing positions at once. With the longer budget, all five trained sources become rank-1 and nearby unseen positions partially generalize.

The object is therefore already more naturally described as a **family of addressed transfer relations** than as one carved path.

### Gates 6–7 — learned addressing, then an ablation that kills frequency as necessary address

Gate 6 adds a fast task-to-address selector while the shared material changes more slowly. The selector starts without task/address knowledge and learns useful physical coordinates from scalar task utility.

Gate 7 then removes address degrees of freedom to see what was actually necessary:

```text
full position x frequency   median worst ratio  1.70577   rank-1 100%
position only               median worst ratio  1.70236   rank-1 100%
frequency only              median worst ratio  0.999996  rank-1 66.7%
```

Position-only retains `99.80%` of the full margin.

Verdict:

```text
position_dominated_joint_not_needed
```

Frequency remains part of the physical transfer function, but it did **not** earn the claim of being a necessary learned address coordinate in that task.

### Gates 8–9 — material can rewrite what a physical address means

Gate 8 attacks the possibility that source position merely labels the blank lattice's native upper/center/lower geometry. It imposes a crossed 3-cycle at fixed frequency:

```text
upper source  -> lower target
center source -> upper target
lower source  -> center target
```

After local conserved learning:

```text
blank worst crossed relation       0.10978x
learned median worst relation      1.52250x
worst learned seed                 1.36263x
rank-1 crossed relations           3/3 in every seed
random structural drift            0.06725x median
```

Gate 9 then audits the actual source-coordinate optimum. Before learning, every target prefers its native source. After crossed learning, the imposed crossed source becomes audit-best for all three targets in all three seeds.

Verdict:

```text
address_optima_move_with_learned_material
```

So `g` can change not just response magnitude under a fixed coordinate, but **which physical coordinate is the best query for a relation**.

## Gate 10 — can material hold and return a dense linear operator?

Gate 10 changes the unit of analysis from one-hot routing to a true vector-space transformation.

Three left input ports and three right output ports expose a dense complex `3x3` matrix:

```math
M_g=C\left[K(g)-\omega^2I+i\omega\Gamma\right]^{-1}B.
```

A hidden physically reachable teacher material generates the target operator. Student material starts blank and sees only **three dense random complex input vectors and their output vectors**. It never sees the hidden `g` and never sees basis vectors during learning.

After learning stops, basis queries `e1,e2,e3` reconstruct the matrix column by column.

```text
blank matrix error                    55.2588% median
reconstructed matrix error             1.7686% median
worst learned seed                     2.7142%
blank held-out dense-probe error       54.3629% median
learned held-out dense-probe error      1.5592% median
random-drift matrix error              59.7667% median
```

So a physically realizable dense operator can be identified through ordinary input/output examples and later recovered from the persistent material.

Then comes the kill test. The same learner is asked to fit an unrelated dense complex matrix that was not generated by any known lattice material:

```text
blank arbitrary-target error          145.6234% median
learned arbitrary-target error         73.1030% median
learned held-out error                 70.7990% median
```

Verdict:

```text
physically_reachable_operator_readback_succeeds_but_arbitrary_matrix_claim_fails
```

So the supported object is a **realizable physical operator family**, not arbitrary matrix RAM.

## Gate 11 — can one `g` hold two addressed dense operators?

This is the first direct test of the proposed advantage over simply storing one matrix.

Two frequency addresses are fixed:

```text
A: omega = 1.20
B: omega = 1.55
```

Each address exposes its own dense `3x3` transfer matrix. Training again uses only dense random probes. A proposed local material transfer receives one scalar consequence based on both address errors; basis vectors remain audit-only.

### 11A — two slices from one hidden material

One hidden teacher material generates both target matrices. Therefore an exact shared solution exists.

```text
blank median worst matrix error       68.6673%
learned median worst matrix error      5.1920%
learned median worst held-out error    4.8928%
worst seed worst-matrix error         17.0797%
random-drift median worst error       72.2012%
```

This passes the preregistered two-address criterion.

> **One persistent material can recover multiple dense addressed operators when those operators are compatible slices of one physical operator family.**

### 11B — independently specified operators collide

Now each frequency receives a target generated by a **different hidden material**. Each target is physically reachable alone, but one common `g` is not guaranteed to satisfy both.

First verify that both are learnable separately:

```text
omega=1.20 isolated median error       2.1744%
omega=1.20 worst seed                  4.1087%

omega=1.55 isolated median error       6.2731%
omega=1.55 worst seed                  7.5729%
```

Both pass.

Then force one shared material to fit both:

```text
blank median worst matrix error       70.5606%
shared-g median worst matrix error    11.2311%
shared-g median mean matrix error      9.8341%
shared-g median worst held-out error  10.8406%
worst seed worst-matrix error         13.0422%
random-drift median worst error       86.1067%
```

The joint learner gets close, but misses the fixed `10%` median-worst matrix and held-out thresholds. Its worst-address error is about `1.790x` the harder isolated fit.

Verdict:

```text
shared_family_recovered_but_independent_operator_programming_collides
```

This is deliberately **not** called a proof that independent operators are impossible. The miss is narrow. It is evidence that changing one `g` couples the addressed operators and creates a measurable interference cost under this budget and local learning rule.

That is exactly the phenomenon the operator-manifold interpretation predicts:

```math
\mathcal M_g=\{M_g(a)\}_{a\in\mathcal A}
```

is one coupled object. A local edit to `g` deforms many exposed matrices simultaneously.

## Why this might matter for AI

The uninteresting interpretation would be:

```text
ordinary matrix -> expensive resonator -> same matrix multiplication
```

There is no obvious reason to want that.

The interesting interpretation is:

```text
one persistent physical state g
        ↓
address / query a
        ↓
M_g(a)
        ↓
vector input x
        ↓
y = M_g(a)x
```

One material may expose a continuum or discrete collection of related operators, while a single physical edit changes the whole collection coherently.

That raises concrete AI questions:

- how many independently useful operators can one shared substrate support?
- which requested edits cooperate, and which collide?
- can address separation reduce interference?
- what is the intrinsic dimension of the realizable operator manifold?
- can a low-dimensional `g` generate a useful structured family more efficiently than storing every matrix separately?
- can a fast query mechanism select an operator while a slow material process continually rewrites the family?

Gate 11 supplies the first direct interference measurement rather than assuming this shared-family property is automatically beneficial.

There is also a direct connection to the `Kompressori` line of work: the relevant object is now the sensitivity of several exposed operators to the same material coordinates,

```math
J_a = \frac{\partial\,\mathrm{vec}\,M_g(a)}{\partial g}.
```

If two desired operator changes demand overlapping but incompatible directions in `g`, their Jacobian geometry should predict the collision before training.

---

## What this does **not** establish

Gates 0–11 establish computational-physics behavior in a deterministic toy only.

They do **not** establish:

- arbitrary matrix realizability;
- scalable multi-model storage;
- compression relative to ordinary digital weights;
- a hardware energy or latency advantage;
- a useful neural network or semantic intelligence;
- autonomous goals;
- biological dendritic credit assignment;
- that the Gate-11 independent-programming penalty is a hard representational limit rather than an optimization limit.

The biology-facing hypothesis remains separate and substantially less established than the physical-operator results.

## Next attack — collision or optimization?

Gate 11's independent-programming miss is too small to narrate as a hard capacity wall.

The next gate should separate two explanations:

```text
A. optimizer/budget problem
   a better or longer local search can drive both operators below 10%

B. operator-manifold collision
   the two requested matrix corrections demand incompatible material directions
```

The clean way to attack this is to combine a **budget curve** with a local Jacobian audit. Measure

```math
J_A=\partial\,\mathrm{vec}M_g(1.20)/\partial g,
\qquad
J_B=\partial\,\mathrm{vec}M_g(1.55)/\partial g,
```

and ask whether the material direction that reduces one operator error predicts damage to the other. Then compare that prediction with what actually happens under longer local learning.

If the error keeps falling, Gate 11 was mostly an optimization limit. If it plateaus while the Jacobian geometry predicts incompatible correction directions, we have something much sharper: **a measurable collision geometry inside a shared physical operator manifold.**
